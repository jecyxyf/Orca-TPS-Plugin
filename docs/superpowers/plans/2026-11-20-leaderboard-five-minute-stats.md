# 天梯榜 5 分钟提交统计开发计划

依据[已确认的设计稿](../specs/2026-11-20-leaderboard-five-minute-stats-design.md)。提交端生成四项统计，服务端保存原值，看榜端随现有榜单请求每 10 秒读取一次。每个周期的前 100 名展示服务器当前保存的最近 5 分钟记录。

计划编写时，`1.6.5` 的 `npm test` 已通过 148 项测试。

## 1. 建立独立开发基线

- [x] 从 `1.6.5` 建立独立开发分支。新功能沿用原有榜单提交和查询接口，实时脉搏是独立功能。
- [x] 以原分支的 148 项测试为基线，覆盖当天用量提交和头像重试等现有榜单行为。

## 2. 保存成功提交的统计点

主要文件为 `server/app.mjs`、`server/store.mjs`、`tests/leaderboard.test.mjs`。

- [ ] 在 `POST /api/today/submit` 读取可选的 `stats`。提供时校验 `deltaTokens` 为非负安全整数、`avgTps` 为有限的非负数或 `null`，模型名和 CLI 限长并接受 `null`。沿用认证、请求体大小、提交编号和限频校验。
- [ ] 在 SQLite 增加短期统计记录，保存账号、请求编号、服务端提交时间和四项原值。为账号与提交时间的查询建索引，并约束同账号同编号只出现一条。沿用 `store.submit()` 的事务写入成绩和点。只在首次通过校验并成功写入成绩的分支新增点，重试返回原处理结果。
- [ ] 查询固定取服务器当前时间前 5 分钟内的记录。沿用现有后台清理路径批量删除过期点。一次读取该榜单周期前 100 名的点，按账号和时间组织结果。
- [ ] 验证旧提交格式、零增量、缺失速度及模型、拒绝提交、原请求重试、跨北京时间零点、双设备和数据库重开。用固定时钟检查 5 分钟边界。

## 3. 提交端采集并发送四个值

主要文件为 `src/data.mjs`、`src/usage-summary.mjs`、`src/computation-worker.mjs`、`src/worker.mjs`、`src/remote-collector.mjs`、`src/remote-channel.mjs`、`src/leaderboard.mjs`，复用 `tests/usage-summary.test.mjs`、`tests/remote-channel.test.mjs` 和 `tests/leaderboard.test.mjs` 的用例结构。

- [ ] 从现有本地与 SSH 解析结果取得已完成请求的标识、完成时间、Token 用量、速度、模型和 CLI。在请求被汇总成每日数据前提取所需字段，沿用现有读日志预算和镜像去重规则。为使用中的会话沿用增量读取。后台采集也纳入统计，覆盖切走频道后继续完成的请求。
- [ ] 建立本地采集起点，保留足以识别重读及重启的处理进度。保留紧凑的近期记录和未确认批次。用该批请求计算 `deltaTokens`，用最近 5 分钟的完成记录计算 `avgTps`、`topModel`、`topCli`。并列时取最近使用的一项，缺数据使用设计稿约定的 `0` 或 `null`。
- [ ] 在 `performSubmission()` 组装原有成绩请求时附上四个值。暂存请求编号、请求体和本批记录。超时重试复用它们，成功后只确认该批；其后产生的请求留给下次。历史初始化沿用原有入口。
- [ ] 验证首次扫描历史日志、日志重读、日期变化、不同项目与远端会话、并列结果、失效速度、丢失确认、重启和提交过程中出现新请求。核对网络请求只有约定的四项统计。

## 4. 用同一个榜单请求读取和绘制

主要文件为 `server/app.mjs`、`server/store.mjs`、`src/leaderboard.mjs`、`src/panel.html`、`src/locales/*.xml`、`tests/leaderboard.test.mjs`、`tests/panel.test.mjs` 和 `tests/locales.test.mjs`。

- [ ] 为公开的 `GET /api/today?days=1&stats=1` 增加 `recent`，按所选周期传 `1`、`7` 或 `30`。以当前周期的排名及前 100 名为准。每个点返回提交时间、新增量和速度，模型与 CLI 每行取最后一笔各返回一次。
- [ ] 每个周期共用公开快照。成绩和榜单变动、北京时间换日、最早的点到期时使缓存失效。公开响应带 `ETag`，内容相同时按 `If-None-Match` 返回 `304`。含本人状态的认证响应走原有查询路径。
- [ ] 在客户端 `fetchState()` 与面板的行数据处理处保留 `recent`。`304` 使用本周期已有快照。打开、手动刷新、切换周期和网络恢复时取完整的当前快照。以当前名单替换本地显示，过期缓存按 5 分钟窗口处理。
- [ ] 将 `RANK_REFRESH_MS` 统一为 `10_000`。今日、近 7 天、近 30 天应用同一间隔，复用现有请求合并和失败退避。榜单隐藏时暂停自动拉取。新增统计随排名一同读取。
- [ ] 每行按设计绘制曲线，按提交时间显示实际点，空档留白。速度、模型和 CLI 用该账号最后一笔短期记录，最后提交时间取榜单成绩时间。用现有国际化机制补充必要文案。
- [ ] 验证首轮快照、`304`、正常 10 秒拉取、两个同时看榜的客户端、第 100 和 101 名互换、断线恢复和过期显示。验证旧版看榜请求可以继续使用原接口，管理员删分和换日能刷新名单。
