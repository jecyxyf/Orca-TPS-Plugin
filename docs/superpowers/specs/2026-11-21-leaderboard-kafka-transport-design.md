# 榜单 Kafka 传输设计

插件通过现有 HTTPS 接口提交数据。服务端把上传包放进 Kafka。四个常驻线程各自取包、批量写 SQLite，再向 Kafka 确认处理进度。另一个线程负责整点算榜。登录方式、插件协议和榜单数据库结构沿用现有方案。

## 初始配置

| 项目 | 配置 |
| --- | --- |
| Kafka | 测试环境使用独立的 Kafka，上传主题设 4 个分区。消息保留期初始设为 3 天，验收时核对积压和磁盘占用。 |
| 取包和写库 | 4 个常驻线程加入同一个消费者组。正常情况下各处理 1 个分区。每个线程用自己的 SQLite 连接，直接调用现有批量写入函数。 |
| 算榜 | 1 个线程。四个分区都到达整点标记后，读取同一份 SQLite 快照来生成四张榜。 |
| 批次 | 有包就取，处理完继续取。初始每批上限为 64 包或 1 MiB。到任一上限就提交，单个合法上传包完整处理。 |

测试服主机实测有 2 个虚拟 CPU、约 3.6 GiB 内存。四个线程可以同时等消息。SQLite 同一时刻允许一个写事务，所以四个线程轮流提交。压测记录消费积压、写入耗时、锁等待和内存。[Kafka 消费者组](https://kafka.apache.org/39/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html) · [SQLite 并发](https://sqlite.org/wal.html#concurrency)

## 收包和写入

| 步骤 | 规则 |
| --- | --- |
| 放进 Kafka | 一次上传对应一个完整消息，带原有上传编号和服务器收件时间。相同账号和来源的包进入同一分区。旧格式的当天和滚动条目随原请求一起处理。 |
| 批量取包 | 线程按分区顺序取包，把一批交给现有 `uploadBatch`。 |
| 写 SQLite | 用账号 ID、来源 GUID 和小时定位唯一一行。在同一个事务里比较更新时间和覆盖范围，再写入。锁等待超时或事务失败时重试本批。 |
| 确认进度 | SQLite 提交成功后，向 Kafka 确认该分区已连续处理完的位置。使用请求关联编号把写库结果送回等待中的 HTTP 请求。等待超时后，插件按已有流程用原上传编号重试。 |

写库成功后进程若在确认 Kafka 前退出，重发的数据仍走同样的唯一键和更新时间判断。共用 SSH 的两台电脑归到同一来源，已有的上报资格和完整覆盖规则继续生效。[KafkaJS 批量读取和手动确认](https://kafka.js.org/docs/consuming)

## 四个分区的整点边界

1. 收包端按服务器收件时间划分整点。等整点前的入队请求得到明确结果，再给四个分区各放一条相同截止时间的标记，然后发送整点及以后收到的包。入队结果无法确定时，保留最近有效榜单，等恢复后补算。
2. 每个分区处理到标记时，先提交前面的数据，再等算榜线程固定读取内容。到达进度按分区计算。遇到线程重启或 Kafka 重新分配分区，可从未确认的标记继续等待。
3. 四个分区都到达后，算榜线程开启 SQLite 读取，固定本次读取内容。四个分区随后继续处理后面的包。算榜线程保存四张榜的统一结果，插件读取最新成功结果。
4. 计算失败或服务重启时，沿用最近有效结果。补算沿用现有小时方案，用已确认的数据生成最近整点的榜单，并记录实际生成时间。用截止时间和分区编号识别重复的整点标记。

## 接入和验收

服务端在 `server/leaderboard-jobs.mjs`、`server/leaderboard-thread.mjs` 和启动代码接入 Kafka，复用 `server/store.mjs` 的批量写入和现有榜单结果表。先用隔离的 Kafka 和测试服数据库副本验证。Kafka 和现有写入方式通过服务端配置切换。回退时先停收、处理完已入队的包，再切换。

| 验收 | 预期 |
| --- | --- |
| 四个分区持续上报 | 四个消费线程分别取包，各自调用 SQLite 批量写入。 |
| 多个线程同时准备写库 | SQLite 轮流提交，锁超时的批次能够重试。 |
| 写入前退出，或写完后确认前退出 | 消费从未确认的位置继续，同一来源同一小时的用量保持正确。 |
| A、B 共用 SSH，收到重复包和迟到的旧包 | 归同一来源，按同一小时的更新时间和完整覆盖规则保留有效小计。 |
| 四个分区先后到达整点标记 | 整点前的数据都写好后，再用同一截止时间生成四张榜。 |
| 切回现有方式 | 已入队的数据能结清，旧客户端继续使用现有协议。 |

测试服对账和压测后，再评估正式服部署。后续增加分区和消费者之前，先确认瓶颈在取包、合并还是写库。
