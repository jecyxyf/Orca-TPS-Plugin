# TPS Plugin 1.6.5 本机存储和按设备上传设计

一台电脑使用一个本机 SQLite 文件。文件里有三张业务表，分别保存单次请求、三个界面的快照和按设备拆开的待上传包。插件通过自己的数据库保存这些数据。Orca 存储继续提供界面设置、已有本机 GUID 和加密登录凭证。

1.6.5 的本机库从空库初始化，按现有采集方式重读最近 30 天仍可访问的原始日志。这个过程只读取日志中的用量字段。测试服的现有榜单记录继续按 [SSH 用量去重设计](./2026-11-21-ssh-usage-deduplication-design.md) 核对和切换。

## 三张本机表

数据库文件建议放在当前 Orca 用户资料目录的 `tps-plugin/usage.sqlite`，沿用项目对 Windows、macOS、Linux 及 `ORCA_USER_DATA_PATH` 的定位规则。用 SQLite 的 `user_version` 记录结构版本。

| 表 | 一行代表什么 | 唯一键 |
| --- | --- | --- |
| `usage_records` | 一次已完成的 AI 请求 | 来源 GUID + 稳定请求编号 |
| `panel_cache` | 一个界面的当前和上次快照 | 界面编号 |
| `upload_queue` | 一个来源的待发送、待确认或已确认的批次 | 服务器地址 + GitHub 账号 + 来源 GUID + 上传编号 |

### `usage_records` 单次请求

| 字段 | 保存内容 |
| --- | --- |
| `device_guid`、`record_id` | 实际产生日志的设备编号和稳定请求编号。优先沿用采集器已有的记录编号。 |
| `completed_at`、`username` | 请求完成的 UTC 毫秒时间和采集时的 GitHub 用户名。未登录时用户名为空。 |
| `harness`、`model` | Codex、Claude Code 等工具和模型标识。 |
| `input_tokens`、`output_tokens`、`cache_read_tokens`、`cache_write_tokens` | 沿用现有 Token 统计口径的计数。 |
| `tokens`、`tokens_per_second`、`duration_ms` | 本次用量计数、可用的生成速度和耗时。日志缺失的指标保存为空。 |
| `workspace_key`、`log_unit_key`、`log_stamp`、`updated_at` | 所属工作区、日志编号、上次成功读取时的日志版本及本次更新的时间。 |

采集器使用日志编号和版本，优先处理发生变化的日志。同一请求重读时更新原行。读取失败时保留上次成功读到的用量，等恢复后再核对。只有完整读取能确认一条旧记录已被修正或移除时，才更正对应的用量。一次修正影响两个不同日期或时间点时，两处都要重新汇总。按来源、完成时间和日志编号建索引，用来查用量范围和清理过期数据。

单条请求只保留最近 720 小时，按完成时间定期清理。个人统计按本地日期计算，榜单每日用量按北京时间计算。个人热力图以这 30 天的明细重算。

### `panel_cache` 界面快照

三个界面各存一行，界面编号分别为 `current-data`、`usage`、`leaderboard`。每行保存当前快照、上次快照及两份快照各自的生成时间和适用范围。范围包含工作区，榜单还包含服务地址、账号和所选周期。

成功取得一份新结果时，在一次数据库写入里把当前快照移到上次，再写入新的当前快照。读取失败时沿用同一范围内最后成功的快照，并显示其原有更新时间。切换工作区、服务地址或账号时按新范围匹配，避免显示上一个范围的数据。

### `upload_queue` 上传队列

一包只有一个来源 GUID。每条保存目标服务地址、GitHub 账号、来源 GUID、上传编号、包内容、状态和时间。变动经过汇总后写入队列，发送前保存完整请求。等待确认期间的用量变化排进后续批次，已经发出的包保持原样。切换到一个尚无上传进度的账号或服务器时，按该目标发出近 30 天的首次批次。

服务器确认后把对应包标记完成。队列在同一张表中记住该来源已经确认的版本和范围，用来继续补传。断网、关闭 Orca 或插件重启后，使用保存的包和原上传编号重试。已确认的数据在移出 30 天范围后可清理。还在统计范围内的待确认包保留到收到明确结果。切换账号或服务地址后，继续使用对应的队列。

## 上传接口

新版插件提交 `POST /api/leaderboard/uploads`。请求顶层按 `username`、`deviceGuid`、`data` 组织。服务端通过有效登录会话确定 GitHub 账号，核对用户名。GitHub 用户改名后的榜单用量仍按内部账号编号归属。

```json
{
  "username": "alice",
  "deviceGuid": "b954427d-20c1-4cc3-9e2d-76c3636fd187",
  "data": {
    "format": 3,
    "operation": "update",
    "requestId": "bc7ffa65-2efa-4e93-9c2c-0f097d2e8945",
    "revision": 12,
    "daily": [{ "day": "2026-11-21", "tokens": 150 }],
    "buckets": [[1795236300000, 100]]
  }
}
```

| 字段 | 用法 |
| --- | --- |
| `deviceGuid` | 本机用已有本机 GUID，SSH 用远端账号存下的固定 GUID。两台电脑连同一个 SSH 账号时使用同一个远端编号。 |
| `data.format`、`data.operation` | 服务端用格式号识别新版，用操作类型区分用量更新、申请写入和分批交接。 |
| `data.requestId`、`data.revision` | 上传编号识别重试，数据版本阻止较旧的上传覆盖当前值。 |
| `data.reporterGuid`、`data.leaseEpoch` | SSH 上报时带本机上报者 GUID 和服务端发的写入资格编号。本机用量的上报者就是来源设备。 |
| `data.daily`、`data.buckets` | 来源设备在某天或某个完成时间点的总量。多条请求同毫秒完成时，先把该来源的用量相加。 |
| `data.coverage`、`data.stats` | 扫全时可报告覆盖范围。速度榜所需的统计字段继续放在该来源的数据里。 |

单包 JSON 保持现有的 64 KiB 上限，大包按实际字节数拆开发送。每个包分别返回确认结果。账号级的旧数据核对沿用现有迁移流程，准备的用量批次同样按来源拆包。

用户改名时，客户端按登录账号的稳定编号继续使用现有队列。服务端仍能按账号、来源和上传编号找到已确认的旧包。待确认的包只有在服务端明确返回改名且原包未入库时，才用新用户名建包。

### 服务端去重

服务端复用按来源保存的用量表。当天榜用「账号 + 来源 GUID + 北京时间日期」定位，滚动榜用「账号 + 来源 GUID + UTC 时间点」定位。数据库直接按唯一键更新。例如同一个 SSH 远端在 10:05 先报 100 Token，后续及时修正为 130，最终保存 130。相同上传编号的重试返回之前的确认结果。

沿用 SSH 的 60 秒写入资格。接手电脑先补齐该远端的完整数据，服务端确认后一次切换。迟到的旧资格或旧版本提交会被拒绝。管理端清分、封禁和上传限制在新版接口继续生效。

服务端通过现有账号状态接口公布支持的上传格式。先更新服务端，再更新插件。客户端在目标服务支持新版格式时启用上述结构。

## 修改范围与验收

| 范围 | 涉及代码 |
| --- | --- |
| 本机数据库和采集 | 新增 SQLite 存储模块，接入 `src/worker.mjs`、`src/usage-summary.mjs`、`src/data.mjs` 和 SSH 采集链路。 |
| 界面快照 | `src/channel-cache.mjs`、`src/worker.mjs`、`src/leaderboard.mjs` 和榜单视图缓存。 |
| 上传队列和服务端接口 | `src/usage-upload.mjs`、`src/leaderboard.mjs`、`server/app.mjs`、`server/source-uploads.mjs` 和关联榜单测试。 |

| 场景 | 通过标准 |
| --- | --- |
| 空库启动与数据量超过 5 MiB | 能建立三张表并读写统计、快照和队列。重读同一日志保持请求总数一致。 |
| 过期数据 | 超出 30 天的单条记录被清理，近 30 天的榜单和个人统计边界正确。 |
| 界面断线和重启 | 恢复同一界面的最后成功快照。切换工作区、账号或环境时使用对应范围。 |
| 断线补传 | 响应丢失和插件重启后，仍用原编号发送同一份包。更新后的本地用量可以继续上报。 |
| 两台电脑共用一个远端 | A 本机 30、B 本机 20、远端 100，最终当天榜和滚动榜均为 150。 |
| SSH 交接和服务器保护 | 旧包迟到、已清分日期、封禁和用户改名时，按对应规则处理。 |
| 完整检查 | 通过 `npm test`、`git diff --check` 和 Orca 插件校验，再安排测试服双机联调。 |

## 本地数据库精简结构

SQLite 结构 2 将请求明细减为 13 列，并在打开旧库时迁移已有数据。图中的状态参数、统一目录、370 天留存和本月统计是后续设计。`./` 以各台电脑的用户主目录为起点。

```text
./orca/tpsplugin/
└── usage.sqlite
    │
    ├── 001 状态参数
    │   ├── 系统参数
    │   │   ├── 本机 GUID
    │   │   └── GitHub 数字 ID
    │   │
    │   └── 实时参数
    │       ├── 本地同步
    │       │   └── 最后获取本地数据的时间
    │       └── 天梯上传
    │           └── 最后成功上传的时间
    │
    ├── 002 请求明细
    │   └── usage_records 表             一次 AI 请求一行，保留 370 天
    │       ├── 身份
    │       │   ├── device_guid          实际产生请求的设备编号
    │       │   └── record_id            稳定的请求编号
    │       ├── 时间
    │       │   ├── completed_at         请求完成时间，用于统计和清理
    │       │   └── updated_at           这行最后更新的时间
    │       ├── 来源
    │       │   ├── harness / model      工具和模型
    │       │   └── log_unit_key         原日志编号
    │       ├── 用量
    │       │   ├── input_tokens / output_tokens
    │       │   └── cache_read_tokens / cache_write_tokens
    │       ├── 性能
    │       │   ├── tokens_per_second   每秒生成速度
    │       │   └── estimated            速度估算标记
    │       ├── 主键                     device_guid + record_id，用于去重
    │       └── 索引                     完成时间、设备+时间、设备+日志
    │
    └── 003 界面快照
        └── panel_cache 表
            ├── panel                    主键，按界面编号存放
            │   ├── current-data        当前会话数据
            │   ├── usage               今天、近 7 天、近 30 天、本月统计
            │   │   ├── 今天            按小时展示，当前小时持续累加
            │   │   └── 本月            从当月 1 日开始累计
            │   └── leaderboard         最近读取的榜单
            ├── current_snapshot         当前快照
            ├── current_scope            当前快照适用范围
            ├── current_at               当前快照生成时间
            ├── previous_snapshot        上一份快照，供界面做变化动画
            ├── previous_scope           上一份快照适用范围
            └── previous_at              上一份快照生成时间
```

两个时间初始留空。本地数据成功写入 SQLite 后更新本地同步时间，收到服务器成功确认后更新天梯上传时间。重复采集按「来源设备 + 请求编号」去重，重复上报按「来源设备 + 小时」更新同一条汇总。

总 Token 和历史缓存命中率由四项 Token 计数计算。界面快照保留当前和上一份。
