# 天梯榜 5 分钟提交统计设计

## 目标

在现有天梯榜上，为所选周期的前 100 名各增加一组最近 5 分钟的提交统计。提交端计算四项数值，服务端记录并随榜单下发，看榜端负责画曲线。这项功能以原有榜单提交和查询为基础，独立于线上实时脉搏。

```text
用户名                                榜单用量
            最近 5 分钟用量曲线
最常用模型 · 最常用 CLI                平均速度
最后提交时间
```

## 统计口径

| 字段 | 提交端计算方式 |
| --- | --- |
| `deltaTokens` | 汇总本次新完成且尚未上报的请求用量，沿用榜单的 Token 口径，包含新输入、输出和缓存读写。没有新增时传 `0`。 |
| `avgTps` | 对最近 5 分钟内有有效速度的请求取平均生成速度，单位为 Token/秒。缺少有效速度时传 `null`。 |
| `topModel` | 按最近 5 分钟的请求次数选出最常用的模型。没有可识别模型时传 `null`。 |
| `topCli` | 按最近 5 分钟的请求次数选出最常用的 CLI。没有可识别 CLI 时传 `null`。 |

最近 5 分钟按请求完成时间计算。最常用项并列时取最近使用的一项。请求次数留在提交端。采集复用本地和远端请求记录，按请求标识去重。首次启用以当前采集位置为起点，后续保留处理进度，历史日志重读和当天累计值都不计入新增用量。

同一笔提交固定请求编号、请求体和包含的请求。客户端确认成功后标记这一批请求已上报，期间完成的新请求留给下一笔。超时重试复用同一个编号与原请求体。

## 提交与服务端存储

沿用 `POST /api/today/submit`，手动和自动提交走同一条路径。认证继续使用 `Authorization: Bearer …`，请求编号使用 `Idempotency-Key`。请求格式如下。

```json
{
  "day": "2026-11-20",
  "installationId": "4284bed6-550c-4e77-958a-20dfec96892a",
  "tokens": 128000,
  "stats": {
    "deltaTokens": 3200,
    "avgTps": 42.6,
    "topModel": "gpt-5.4",
    "topCli": "codex"
  }
}
```

`tokens` 为当天累计用量。`stats` 为选填项，旧版客户端可继续按原格式提交。服务端从登录会话取账号，从服务器时钟取提交时间。四项统计在通过类型、取值和长度校验后按原值保存。成功响应沿用 `code: accepted`、`submittedAt` 等现有字段。

成绩和新点在同一个 SQLite 事务内保存。每次携带 `stats` 的新成功提交生成一个点，`deltaTokens` 为 `0` 也生成点。同一提交编号只保存一次。短期记录按账号和服务器提交时间读取，只返回最近 5 分钟的点，过期记录批量清理。

## 榜单拉取与展示

| 时机 | 处理方式 |
| --- | --- |
| 正常查看 | 今日、近 7 天、近 30 天共用 10 秒自动拉取间隔，与自动提交间隔一致。新增统计随当前榜单请求返回。 |
| 打开、切换周期、手动刷新 | 立即读取所选周期当前的前 100 名和对应的用量图记录，随后恢复 10 秒间隔。 |
| 断线恢复 | 读取服务器此刻的快照，替换本地数据。 |
| 离开榜单 | 暂停看榜的自动拉取。 |

今日榜用提交时间画最近 5 分钟的点。近 7 天和近 30 天榜使用 `daily=1`，每行额外返回 `daily`，由已有的每日榜单成绩组成，格式为 `{ day, tokens }`。日期按北京时间划分，窗口包含今天，缺记录的日期留空。每天的点显示该账号在当天的累计用量。日曲线响应只带最近一笔提交的短期数据，供卡片显示速度、模型和 CLI。

新版使用 `GET /api/today?days=1&stats=1` 请求完整榜单，`days` 可为 `1`、`7` 或 `30`。公开快照按周期共用。正常自动拉取使用 `If-None-Match` 带上上一份快照的 `ETag`，服务端在快照内容一致时返回 `304`。打开、切换周期、手动刷新和断线恢复时取完整快照。缓存到下一条记录过期时也要更新。新增统计沿用同一次榜单请求，进出前 100 名以该次返回的名单为准。

每行在原有排名、用户名、累计用量和最后提交时间之外增加 `recent`。曲线点按服务器提交时间排列，只下发绘图所需的提交时间、新增 Token 和该点的平均速度。最常用模型和 CLI 取该用户最后一笔统计中的值，每行各发一次。时间为 Unix 毫秒。

```json
{
  "rank": 1,
  "username": "example-user",
  "tokens": 128000,
  "submittedAt": 1795145800000,
  "recent": {
    "points": [
      { "submittedAt": 1795145790000, "deltaTokens": 2100, "avgTps": 39.2 },
      { "submittedAt": 1795145800000, "deltaTokens": 3200, "avgTps": 42.6 }
    ],
    "topModel": "gpt-5.4",
    "topCli": "codex"
  }
}
```

看榜端用名单渲染卡片，有变化的行才更新显示。顶部用量对应所选榜单周期，底部时间取榜单成绩的最后成功提交时间。今日榜曲线合并同账号所有设备的提交点。速度、模型和 CLI 显示最近一笔统计所在设备给出的值，最近 5 分钟没有记录时显示 `—`。各周期的曲线按实际记录绘制，空档留白。

## 修改范围与验收

| 范围 | 验收内容 |
| --- | --- |
| 插件采集、提交与拉取 | 四项统计由提交端算好。同一请求重读、重试各只计一次。三种榜单周期均按 10 秒自动拉取，手动刷新立即返回当前数据。 |
| 榜单服务与 SQLite | 新旧格式均可提交。成绩和新点一起保存。重复提交只产生一个点。第 100、101 名互换时返回正确名单。快照内容一致时可复用，记录过期后从返回结果移出。 |
| 侧栏卡片和文案 | 两个看榜端能看到同周期的相同数据。重连显示服务器当前快照，空档留白。原有榜单用量、头像、名次和提交时间通过回归测试。 |
| 用户说明 | 功能验证后，使用 `docs-update` 检查中英文 README 和 Orca 插件目录，按需更新。 |
