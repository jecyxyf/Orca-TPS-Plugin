# SSH 用量去重设计

同一个 GitHub 账号在两台电脑上连接同一个 SSH 账号时，远端用量只算一次。本机用量仍按各自的设备累计。目标覆盖当天用量和近 24 小时、7 天、30 天的滚动用量榜。

例如 A 本机用了 30 Token，B 本机用了 20 Token，远端用了 100 Token。即使两台电脑都读到远端这 100 Token，榜单合计也是 150 Token。

## 给每份用量一个固定来源

| 来源 | 编号规则 |
| --- | --- |
| 本机 | 沿用 Orca 插件已有的随机设备 GUID。 |
| SSH | 第一次为榜单采集时，在远端用户数据目录的 `orca-tps-plugin/source-id` 保存一个随机 GUID。目录优先使用 `XDG_DATA_HOME`，默认使用 `~/.local/share`。 |

两台电脑通过不同地址或 SSH 别名连接同一台主机的同一个远端账号时，读取的是同一个文件。采集器先写好临时文件，再以独占方式发布。并发首次创建时，所有采集器都读取先发布的有效 GUID。文件只供远端用户读写。读取失败或内容无效时，保留这个来源上次成功的用量，等下次重试。统计日志和项目文件保持只读。

远端采集器返回 GUID 和统计结果，客户端按 GUID 识别和缓存远端来源。榜单服务只接收来源编号、时间和统计数值。个人统计继续展示用量合计，连到同一来源的两个 SSH 别名使用同一份远端统计。

## 上报与服务器计数

现有上传接口增加按来源提交的格式。一轮上传带上本机上报者的设备编号和各个来源的数据。每个来源带自己的 GUID、类型、当天总量及滚动用量批次。服务端逐个返回保存结果。一次请求沿用现有大小上限，大批次按现有规则分次发。

| 数据 | 保存方式 |
| --- | --- |
| 当天用量 | 按 GitHub 账号、来源 GUID 和北京时间日期保存每个来源的总量，再按账号合计。 |
| 滚动用量 | 按 GitHub 账号、来源 GUID 和请求完成时间保存。同一时间点的补报更新原值。 |
| 上报记录 | 用本机设备编号识别上报者和重复请求。GitHub 账号继续使用现有上传间隔。 |

服务器复用现有的按设备和时间保存用量的表。在按来源格式里，表中的设备编号字段存放来源 GUID。上传顺序、上报者和迁移进度由服务端单独记录。榜单周期和曲线继续从用量数据计算。

### 两台电脑同时连接时怎样更新

同一个 GitHub 账号的同一个远端 GUID，同一时刻由一台电脑负责写入远端用量。服务器给最近成功采集这个远端的上报者发放 60 秒的写入资格。当轮采集成功即可随正常上传续期。两台电脑都能读取远端用量，也都能独立提交自己的本机用量。远端断线、插件退出或原上报者停止提交后，另一台电脑可以在资格到期后接手。

服务器每次分配写入资格时发放递增的编号。每个远端批次带上该编号、批次版本和请求编号。同一批次重试沿用原编号。已经失效的上报者、较旧的批次和重复请求无法覆盖已保存的新数据。

换电脑接手时，先从远端重新读取并分批准备当前最多 30 天的用量。服务端在确认覆盖范围完整后一次性替换该来源的对应记录，再接收后续的增量。准备期间，榜单继续读取上一次完整提交。扫描只完成一部分时，可以继续读到此前的用量，缺失部分等完整读取后再更新。

## 现有数据怎样切换

空数据库可以直接用按来源格式。测试服已有的旧上报把本机和 SSH 用量合在同一个设备编号里，需要从原日志重算才能拆开。

1. 服务端按账号列出当前统计范围里还有数据的旧设备编号，保留这些账号现有的榜单结果。
2. 能重读日志的旧电脑分批准备本机和远端各自的用量。同一远端 GUID 的数据合并成一份。读不全的旧记录等日志恢复，或等它自然移出统计范围。
3. 该账号仍需保留的旧记录都能对应到完整的新数据后，服务端在一次数据库事务中替换旧汇总，启用按来源计数。事务内核对各旧设备最后一次上报的版本。准备期间有新的旧格式上报时，补齐再切换。迁移完成前，榜单读取原有数据。迁移中断可以从已确认的批次继续。
4. 完成切换的账号使用按来源格式提交。如果旧插件继续向该账号上传，服务端提示升级，避免旧混合总量被再次加进来。旧版的榜单查询继续可用。账号的封禁、禁传和已删除日期仍以服务器现有记录为准。

## 实施范围与验收

| 验收场景 | 预期结果 |
| --- | --- |
| 两台电脑首次同时连接同一 SSH 账号 | 生成并使用同一个远端 GUID。用不同的 SSH 别名连接也能识别。 |
| A 本机 30、B 本机 20、同一远端 100 | 当天榜和滚动榜都合计 150 Token。另一个远端账号的用量独立记录。 |
| 上报电脑换手、旧批次迟到或响应丢失 | 换手前的数据可读，旧批次无法覆盖新数据，同一批次重试只保存一次。 |
| 远端断开、日志目录打不开或补传中断 | 保留之前的数字。恢复后继续补传，完整数据到齐后更新榜单。 |
| 测试服已经有 A 和 B 各自上传的混合用量 | 旧汇总和新拆分数据只生效一份。日志读全后可从 250 校正到 150。读不全时保留旧值。 |
| 同账号的旧版插件在切换后上传 | 收到升级提示。榜单还可以查询。 |

后续实施涉及 SSH 采集器和读取端、用量索引、上传代码、榜单服务及其测试。先在本机验证，再用测试服的两个客户端核对合计值和换手结果。改动完成后更新问题清单和部署说明。
