# CC Switch 原版 Token 统计接入

## 目标

TPS Plugin 使用 CC Switch 4.0.25 的原版代码扫描、补扫、去重、入库和汇总 Token 用量。版本固定在 `a3eafa408ae679db2e3401fca767ed2b89d9a2b2`。以同一批日志、相同筛选条件和时间范围为基准，对账结果逐项相等。

## 数据怎么走

1. 独立接入进程使用原版 Rust 库。调用 `sync_session_usage` 处理日志和扫描进度，调用 `get_usage_summary`、`get_model_stats` 和 `get_usage_trends` 返回原版结果。需要请求明细时调用 `get_request_logs`。用量源文件和计算代码按固定版本原样构建。
2. 用量库由原版管理，同一数据源重扫由原版去重。测试使用独立目录。需要已有的 CC Switch 请求明细或按天归档时，通过 SQLite 的一致性备份取得副本，原版在副本上查询和同步。初始化和补扫使用同一个副本，保留该副本自己的进度。
3. `src/worker.mjs` 接到原版同步和查询结果。`src/record-usage-index.mjs` 把接入范围内的用量从原版结果送到现有面板入口。`src/data-paths.mjs` 负责定位原版库和插件使用的接入进程。连接层负责日期边界、筛选条件和字段映射。
4. 范围以该版本原版支持的本机会话和代理日志为准。对账按同一应用、数据源和时间范围比较。对于只保留按天汇总的旧数据，显示原版能返回的粒度。

## 切换和错误处理

用量接入先完成首次同步和对账，再切换面板的数据入口。旧插件库和用户的 CC Switch 原库都可以用于对账。原版查询失败时，面板显示最近一次成功的结果和更新时间，同步完成后再刷新。同步与正在进行的同一轮任务共用进度，避免重复扫描。

## 验证

| 检查项 | 通过条件 |
|---|---|
| 源码一致 | 原版同步和汇总代码与固定提交的文件逐字节一致。 |
| 本机 Codex 对账 | 对此前发现差额的同一批日志，分别检查请求数、新增输入、输出、缓存读取、缓存写入和总量。每项与原版结果相等。 |
| 补扫及去重 | 首次同步后追加日志并增加一个短会话。下轮同步补齐对应记录。原样再同步一次，计数和用量相同。 |
| 其他本地来源 | 对原版和插件共同覆盖的来源逐一校验，包括日志、代理、两者同时存在、按天归档的情况。 |
| 插件使用 | 验证个人统计的当日、滚动范围、模型汇总和历史图。校验接入进程在插件支持的平台上的运行和权限。 |

原版入口由 `cc_switch_lib` 导出。Windows 验证程序在独立测试目录编译并调用了 `sync_session_usage` 和 `get_usage_summary`。原版源码一致性、本机 Codex 对账、新会话补扫、已有日志续写和重扫去重均通过。涉及本机用量的测试输入放在临时目录。正式接入时使用同样的原版入口。 [原版用量入口](https://github.com/farion1231/cc-switch/blob/a3eafa408ae679db2e3401fca767ed2b89d9a2b2/src-tauri/src/commands/usage.rs)
