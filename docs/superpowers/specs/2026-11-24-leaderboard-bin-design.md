# 天梯榜服务改用单个状态文件

## 目标和范围

服务端使用一个 `leaderboard.bin` 保存需要跨重启保留的数据，运行时移除 SQLite。插件沿用 1.6.5 的 Tokens 管家接口和 GitHub 登录流程。管家所在主机上的个人统计继续使用现有存储。

| 功能 | 改法 |
| --- | --- |
| 登录和账号 | 保留 GitHub 登录、退出、有效登录凭证、管理员绑定和封禁原因。管理页可以查找账号、封禁和解封，并显示最近 25 条账号管理操作。 |
| 实时榜单 | 保留配置、账号、上传和四榜快照接口。统计包和榜单快照留在内存，服务重启后由管家重新上报。 |
| 旧版榜单 | 移除旧版上传、查榜、历史初始化、Kafka 写入和管理页的旧榜成绩操作。旧版客户端的榜单功能停用，旧榜历史随旧库清理。 |

## 数据怎么保存

`leaderboard.bin` 是一个 JSON 对象的 UTF-8 字节。对象包含格式版本、GitHub 账号、管理员账号 ID、封禁状态及原因、有效会话和最近的账号管理操作。会话保存凭证摘要、账号 ID、类型和到期时间。

服务启动时读取并校验文件。新安装从空状态开始，文件内容损坏时停止启动并报告错误。账号、登录和管理操作由服务进程统一写入。先在同目录写出临时文件，刷盘后替换正式文件，替换成功后再更新内存和返回成功。文件权限设为 `0600`。已到期的会话会被拒绝，并随下次保存清理。

| 位置 | 状态文件 |
| --- | --- |
| 本地默认 | `server/.data/leaderboard.bin` |
| Docker | `/data/leaderboard.bin` |
| 测试服 | `/var/lib/orca-tps-test/leaderboard.bin` |

路径由 `LEADERBOARD_STATE_FILE` 指定。榜单需要的时区方法放到独立的共享模块，服务启动和算榜线程可以直接使用。

## 测试服切换

1. 停止测试服务。用一次性迁移命令只读打开旧库，把账号、仍有效的会话、管理员、封禁和最近的账号管理操作写入 `.bin`。迁移结束后读回文件并核对记录。
2. 启动新版服务，核对 GitHub 登录入口、账号和封禁状态、上传、四榜快照，再重启一次验证持久化。切换期间用旧程序和原库回退。
3. 验证通过后，删除测试服的 `leaderboard.sqlite` 和该库仍存在的 SQLite 临时文件。测试服日常运行使用 `.bin`。

## 修改和验收范围

涉及服务端入口、登录和管理相关接口、存储、旧榜单任务和部署说明。共享时区模块和相关回归测试一起调整。

| 验收 | 检查内容 |
| --- | --- |
| 文件 | 带有效会话和封禁记录的旧库能一次迁移。文件重启后可读，写入失败时保留上次成功保存的内容，损坏时启动报错。 |
| 登录 | 用模拟 GitHub 验证首次登录、已有会话、退出、管理员绑定和封禁。 |
| 榜单 | 通过新版接口登录、上报和查看四张榜。重启后用管家重新上报恢复。 |
| 服务 | 测试服删除旧库后重启成功，服务仍只写 `leaderboard.bin`。 |
