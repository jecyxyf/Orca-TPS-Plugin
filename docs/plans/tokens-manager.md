# Tokens 管家方案

**每台主机运行一个管家。管家扫描会话、保存用量，主动推送当前频道的请求明细和个人统计。Orca 插件展示当前频道、合并各台设备的个人统计，并从服务器读取天梯榜。**

## 启动、连接和退出

Orca 插件从本机或远程主机的 `~/.orca/tpsplugin/bin/token_manager.mjs` 启动管家。[入口源码](../../src/token_manager.mjs)负责启动、调度、上报和退出。安装目录只放入口和下面五个模块，安装指纹 `bundle-version` 放在上一级。

| 模块 | 职责 |
|---|---|
| [orca_connection.mjs](../../src/orca_connection.mjs) | 连接 Orca，处理订阅、心跳和频道通知，推送当前频道的请求明细。 |
| [harness_parser.mjs](../../src/harness_parser.mjs) | 按起始时间读取 16 种工具的原始日志和数据库，返回 Token 用量和请求明细。 |
| [database.mjs](../../src/database.mjs) | 读写管家的数据库，保存扫描进度、去重状态、明细和汇总。 |
| [personal_stats.mjs](../../src/personal_stats.mjs) | 计算个人用量和速度统计。 |
| [leaderboard_stats.mjs](../../src/leaderboard_stats.mjs) | 计算本机的榜单指标，生成上报包。 |

| 场景 | 处理规则 |
|---|---|
| Orca 插件启动 | 分别检查本机和每台已连接的远程主机。先尝试连接现有管家，确认未运行再启动。管家打开数据库并接受订阅后回复「已就绪」。补算期间只向插件报告进度，补齐用量后才传输统计。 |
| 启动失败或连接中断 | 每隔 **3 秒**重试。本机和远程启动入口共用同一把系统锁，同一台主机只运行一份管家。 |
| 本机和远程订阅 | 本机直接连接管家。远程使用 Orca 的 SSH 配置，由插件另开一条连接。一个 Orca 在同一台主机上的多个项目共用一条订阅。 |
| 短暂断网 | 建议每 **5 秒**报到一次，距离上次报到 **15 秒**才移除订阅。第 4 秒恢复时接回原管家。 |
| 正常关闭 | 收到取消订阅就立即移除。最后一条订阅结束后，管家完成正在进行的数据库写入，再退出。Orca 后来重新连上时，从保存的进度继续。 |

## 扫描与保存

| 项目 | 处理规则 |
|---|---|
| 扫描来源 | Windows 和 Linux 管家统一通过 [HarnessParser](../../src/harness_parser.mjs) 读取 16 种工具的本地日志和数据库。Claude Desktop 读取 Cowork 的本地审计日志和用量流水，同一请求只计一次。GitHub Copilot CLI 读取用量事件，WorkBuddy 读取主会话和子代理日志，DeepSeek Harness 读取普通或 Zstd 压缩会话日志。工具的用量字段参考 [CC Switch 4.0.39 源码](https://github.com/farion1231/cc-switch/blob/768eec9ca94db629f086e8c01ca91e2f63bb273d/src-tauri/src/services/session_usage.rs)。 |
| Hermes | [HarnessParser](../../src/harness_parser.mjs) 从 `agent.log` 和轮转日志读取用量和耗时，从 `state.db` 补工作目录。整机扫描和当前频道查询共用这套读取代码。 |
| 首次补算 | 初始同步时间戳为 `0`，补齐现有日志中最近 **370 天**可获取的用量。损坏的日志静默跳过，继续扫描其余日志。明细和日汇总都完成后，才向插件推送个人统计并向服务器上报天梯榜。 |
| 持续刷新 | 初始化后按服务器下发的间隔刷新。上一轮未结束就等它结束。本轮明细和汇总都保存后才发布新的统计。超过 370 天的数据自动清理。 |

### 数据库内容

| 数据 | 保存内容 |
|---|---|
| 管家设置 | 设备 GUID、GitHub 账号绑定、统计时区和刷新间隔。重启或重建数据库时沿用原设备 GUID。 |
| 日期进度 | 每天的采集进度、各来源的扫描位置、已计入的请求标识和待汇总的批次，用于续扫、去重和恢复日汇总。 |
| 明细数据 | 最近 **32 天**的逐条请求，保存请求 ID、毫秒完成时间、项目、工具、模型、Token 分项、速度，以及日志中可取得的会话 ID 和工作目录。 |
| 单天数据 | 最近 **370 天**每天的用量汇总，按项目、工具和模型保存，包含有逐条明细的最近 32 天。每天同时保留小时小计，供现有面板按整点统计长周期用量。汇总保留请求数、Token 分项、速度总和、速度样本数和估算样本数。 |

管家使用 `~/.orca/tpsplugin/database/tpslugin.db`。每批请求的明细、每日和每小时汇总、扫描进度在同一笔事务里保存。升级时将旧 `daily.db` 的汇总并入 `buckets` 表，只补算尚未写入汇总库的旧批次。合并事务提交后清理旧汇总库。

自然日统计和热力图使用每日汇总。近期或需要逐条核算的区间使用明细，较早的整点区间使用小时小计。同一笔用量只计一次。

## 刷新间隔

服务器统一下发刷新间隔，可分别设置管家扫描用量、个人统计更新、上报和读取榜单。各项默认 **5 秒**，服务固定每 **5 秒**发布一次榜单。插件和管家从下一轮开始采用新的配置。

暂时取不到配置时，沿用上一次有效配置。首次运行时用默认的 5 秒，个人统计也能继续工作。数据库补齐后，管家按上报间隔发送完整统计。榜单每轮使用该轮收到的上报。

## 个人统计与天梯榜

| 功能 | 处理规则 |
|---|---|
| 个人统计 | **无需 GitHub 登录。** 管家向通过本机或已有 SSH 项目连接的插件推送。插件按设备 GUID 和项目汇总，同一设备通过多个项目连入时，整机用量只计一次。统计内容沿用现有面板，包括总 Token、请求数、工具和模型用量、速度与每日热力图。年度范围包括「今年」和「过去 365 天」。[现有面板](../../src/panel.html#L718) |
| 远程缓存 | 管家按来源设备把统计包保存在 `~/.orca/tpsplugin/remote_device/<设备ID>/`。`personal.json` 保存最新个人统计，`leaderboard.json` 按账号保存最新榜单包。Orca 从本机管家读取这些统计，按用量的原始日期和小时合并，并显示更新时间。 |
| 天梯榜上报 | 一台主机绑定一个 GitHub 账号。登录后由管家通过 HTTPS 上报本机和缓存的同账号榜单包。榜单包包含榜单需要的小时用量、每日用量及近期速度统计。没登录时暂停上传，个人统计照常。[现有榜单统计](../../src/submission-stats.mjs#L60) |
| 天梯榜合并 | 同一账号下，每台来源设备只取本轮收到的**原始毫秒时间戳最新**的一份，再把所有设备合成一条成绩。管家原样转发，保留来源 GUID 和原时间戳。原始用量时间决定这笔数据算在哪个周期。 |

## 时区

首次由本机系统时区确定统计时区，远程管家跟随发起连接的本机。用户在本机 Orca 手动修改后，本机和连上的远程管家都按新时区重建统计。重建期间只报告进度，补算完成后再发布统计。插件只合并同一统计时区的数据。重算范围取决于各台主机还保留了哪些原始日志。

## 插件端

| 功能 | 处理方式 |
|---|---|
| 启动和订阅 | 插件启动后连接本机及远程项目的管家。每台主机共用一条订阅，失败每 3 秒重试。 |
| 个人统计 | **无需 GitHub 登录。** 管家主动推送本机统计，插件按设备 GUID 和项目合并。同一设备通过多个项目连入时，整机用量只算一次。保留现有面板的自然日和整点统计、用量与速度展示。插件先合并各设备的用量、速度总和和样本数，再计算总量、均速和模型排名。现有面板可以沿用后台推送入口。[现有推送入口](../../src/panel.html#L1559) |
| 跨设备同步 | Orca 提供已连的 SSH 主机信息，管家用单独的 SSH 连接互传所有已知设备的最新统计。接收方跳过本机设备 ID，仅用原始统计时间更新较旧的包。两台远端可经同一台已连接的主机互传。 |
| 缓存与离线 | 重连时交换各自保存的统计。管家按当前登录账号统一上报各设备用量。服务端按原始设备 ID 去重，按用量发生时间计算对应时段的榜单。 |
| 登录与榜单 | 插件负责 GitHub 登录、退出和把榜单凭证交给管家。插件从服务器读取榜单结果，榜单上报由管家完成。 |
| 刷新与时区 | 采用服务器下发的间隔，默认 5 秒。用户修改时区时，把设置发给本机和已连的远程管家，收到同一时区的结果再合并。 |

### 当前数据与频道

| 步骤 | 处理方式 |
|---|---|
| 登记频道 | 插件从 Orca 获取频道 ID、工作树路径和已有的「工具 + 会话 ID」，通过所在主机的管家连接登记。一条主机连接可以登记多个频道。[现有频道识别](../../src/active-conversation.mjs#L52) |
| 管家读取并推送 | 管家按已知会话或工作树路径匹配请求。同一请求同时匹配会话和路径时只算一次。32 天明细库里的频道请求不足 100 条时，从仍在的原始日志补读，超过明细保留期的记录只用于频道展示。推送带上**设备 GUID 和频道 ID**，每条请求带请求 ID、毫秒完成时间、Token 分项、速度和可取得的首字耗时等卡片字段。[现有频道匹配](../../src/harness_parser.mjs) |
| 插件筛选和展示 | 插件按当前选中的**设备 GUID + 频道 ID**筛选收到的明细，去重后按请求完成时间从新到旧排序，显示最近 **100 条**。本机和远端的同名频道通过设备 GUID 区分。 |

## 服务端

| 功能 | 处理方式 |
|---|---|
| 下发配置 | 可分别设置管家扫描、个人统计更新、榜单上报和榜单读取间隔，默认均为 5 秒。服务固定每 5 秒发布榜单。配置可在未登录时读取，暂时取不到就用上次有效值。数据库补齐后，日常增量扫描还在跑时可以原样重发上一份完整统计。 |
| 接收上报 | 多个接收线程用现有 GitHub 登录凭证确认账号，校验后将统计包放入内存。每份统计包带**来源设备 GUID、来源管家的原始毫秒时间戳、小时用量和速度统计**。[现有账号校验](../../server/app.mjs#L537) |
| 去重与下榜 | 两个接收线程共用一块内存，每个线程满 **1 秒**或攒到 **32 个包**就持锁批量写入。一个算榜线程每 **5 秒**切换双缓冲，在锁外合并已写入的数据。按「账号 + 来源设备 GUID」取原始时间戳最新的一份。设备漏报一轮就退出本轮，下轮写入后重新参与。 |
| 计算榜单 | 管家提供 **24 小时、7 天、30 天**榜所需的小时用量，并提供 7 天和 30 天曲线所需的每日用量。近 5 分钟展示和近 24 小时速度榜所需的样本也由管家随包发送并保留原始时间。服务器从当轮收到的有效包中去重和合并，用量包和榜单结果只放在内存里。[现有榜单周期](../../src/leaderboard_stats.mjs) · [现有速度榜](../../server/store.mjs#L162) |
| 发布榜单 | 汇总线程完成计算后发布一份带版本的榜单结果。所有插件下载或订阅同一版本，收到新结果后更新屏幕。接收线程继续收包，供下一轮计算。 |
| 接入现有服务 | 沿用现有 GitHub 登录和账号管理。新榜单用独立的内存处理入口，先在测试服验证，再切换插件的数据来源。切换时每台设备只走一套上报流程，避免重复计入。 |

## 实施与验收

1. **先做单机管家**，验证空库补算、坏日志静默跳过、370 天保留、默认 5 秒刷新、32 天明细与日汇总交接、单库原子写入，以及升级时旧汇总批次只计一次。
2. **接入本机与远程 Orca**，验证两端均从 `~/.orca/tpsplugin/bin/token_manager.mjs` 启动管家，未登录也能合并本机和远端的个人统计。验证多项目只启动一个管家、启动失败每 3 秒重试、第 4 秒恢复时不重启，以及最后一条连接断开后退出。验证 Hermes 请求和用量、同名频道切换、旧频道补读，以及所选频道最近 100 条按完成时间倒序排列。
3. **验证三台主机合并**，覆盖多份副本取最新、离线缓存按原时间归入所选范围、自然日与整点统计、时区重算时保留设备 GUID，并完成管家的榜单打包与发送入口。
4. **联调服务端和插件**，先在测试服验证多线程收包、单线程按时汇总、各插件取得同一版本的榜单、同账号多设备合成一条成绩、重复代报只计一次、每日曲线来自管家上报、过期数据在下一轮汇总后下榜、服务器重启后随管家重新上报恢复，以及刷新配置更新。
